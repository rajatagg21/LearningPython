# 1. Object Lifecycle

This is how Python **creates and destroys objects**.

## `__new__`

**Responsible for actually creating the object.**

Signature:

```python
def __new__(cls, *args, **kwargs)
```

It must **return an instance**.

Flow:

```
__new__  → creates object
__init__ → initializes object
```

### Example

```python
class User:
    def __new__(cls, *args, **kwargs):
        print("Creating instance")
        return super().__new__(cls)

    def __init__(self, name):
        print("Initializing instance")
        self.name = name


u = User("Rajat")
```

Output

```
Creating instance
Initializing instance
```

### Production use cases

Rare but important:

1. **Singleton pattern**
2. **Immutable objects**
3. **Subclassing builtins** (`int`, `tuple`, `str`)

Example: Singleton

```python
class Database:

    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
```

---

## `__init__`

This **initializes an already created object**.

You **never return anything**.

Bad engineers write:

```python
return something
```

That’s wrong.

Correct:

```python
class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age
```

Production usage:

* validation
* dependency injection
* building internal state

Example

```python
class Config:

    def __init__(self, settings: dict):
        if "db_url" not in settings:
            raise ValueError("db_url required")

        self.settings = settings
```

---

## `__del__`

Destructor.

Runs when object is **garbage collected**.

Example

```python
class FileHandler:

    def __init__(self, path):
        self.file = open(path)

    def __del__(self):
        self.file.close()
```

### Reality check

Good engineers **almost never rely on `__del__`**.

Why?

Because **GC timing is unpredictable**.

Production pattern instead:

```
context managers
```

```
with open(...) as f:
```

So remember:

```
__del__ is unreliable for resource cleanup
```

# 2. Representation

This is about **debugging and printing objects**.

---

## `__repr__`

Goal:

```
Developer representation
```

Rule:

```
repr(obj) should ideally recreate the object
```

Example

```python
class User:

    def __init__(self, name):
        self.name = name

    def __repr__(self):
        return f"User(name={self.name!r})"
```

```
>>> u
User(name='Rajat')
```

Production systems rely heavily on this for:

* logs
* debugging
* traceability

---

## `__str__`

Human readable.

Example

```python
class User:

    def __str__(self):
        return f"User: {self.name}"
```

```
print(user)
```

calls `__str__`.

If missing → Python falls back to `__repr__`.

---

### Production Rule

Always implement **`__repr__`**.

Implement `__str__` **only if needed**.

# 3. Comparisons

These power sorting, sets, dict keys.

---

## `__eq__`

Equality operator.

```
a == b
```

calls

```
a.__eq__(b)
```

Example

```python
class User:

    def __init__(self, user_id):
        self.user_id = user_id

    def __eq__(self, other):
        return self.user_id == other.user_id
```

---

## `__lt__`

Less than.

Used in sorting.

```
a < b
```

Example

```python
class Score:

    def __init__(self, value):
        self.value = value

    def __lt__(self, other):
        return self.value < other.value
```

Now sorting works.

```
sorted(scores)
```

---

## `__gt__`

Greater than.

```
a > b
```

But real production code usually uses:

```
functools.total_ordering
```

Example

```python
from functools import total_ordering

@total_ordering
class Score:

    def __init__(self, value):
        self.value = value

    def __eq__(self, other):
        return self.value == other.value

    def __lt__(self, other):
        return self.value < other.value
```

Python auto-generates the rest.

---

## `__hash__`

Used when object is **key in dict or set**.

Rule:

```
if a == b
then
hash(a) must equal hash(b)
```

Example

```python
class User:

    def __init__(self, user_id):
        self.user_id = user_id

    def __eq__(self, other):
        return self.user_id == other.user_id

    def __hash__(self):
        return hash(self.user_id)
```

Now:

```
set([user1, user2])
```

works correctly.

# What You Should Now Understand

You should see a pattern.

Python syntax is **just sugar for method calls**.

```
len(obj)     → obj.__len__()
obj[0]       → obj.__getitem__(0)
a + b        → a.__add__(b)
a == b       → a.__eq__(b)
obj()        → obj.__call__()
```

Python is basically a **protocol-based language**.

# Exercise 1 — `Money`

Your code:

```python
def __hash__(self):
    return hash(self.amount)
```

❌ **Wrong. Very wrong.**

Remember the rule:

```
if a == b  → hash(a) == hash(b)
```

Your equality depends on:

```
amount AND currency
```

But your hash depends only on:

```
amount
```

This breaks hashing correctness.

### Correct version

```python
def __hash__(self):
    return hash((self.amount, self.currency))
```

Always hash **the same fields used in equality**.

---

### Problem 2

You used:

```python
(self.currency == other.currency) & (self.amount == other.amount)
```

❌ Bad.

`&` is **bitwise operator**, not logical.

Use:

```python
and
```

Correct:

```python
def __eq__(self, other):
    if not isinstance(other, Money):
        return NotImplemented
    return (
        self.currency == other.currency
        and self.amount == other.amount
    )
```

Notice something important:

```
return NotImplemented
```

This is **correct Python protocol behavior**.

---

### Problem 3 — `__repr__`

You wrote:

```python
Money(amount=10,currency=USD)
```

❌ Currency should be repr-safe.

Correct:

```python
return f"Money(amount={self.amount}, currency={self.currency!r})"
```

`!r` ensures proper quoting.

---

### Production version

```python
class Money:

    def __init__(self, amount, currency):
        self.amount = amount
        self.currency = currency

    def __add__(self, other):
        if not isinstance(other, Money):
            return NotImplemented

        if self.currency != other.currency:
            raise ValueError("Currency mismatch")

        return Money(
            self.amount + other.amount,
            self.currency
        )

    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented

        return (
            self.amount == other.amount and
            self.currency == other.currency
        )

    def __hash__(self):
        return hash((self.amount, self.currency))

    def __repr__(self):
        return f"Money(amount={self.amount}, currency={self.currency!r})"
```

# Exercise 2 — `MyList`

You wrote:

```python
def __int__(self, items):
```

❌ Completely wrong.

It should be:

```
__init__
```

So your class **never initializes `items`**.

---

### Correct

```python
class MyList:

    def __init__(self, items=None):
        self.items = list(items) if items else []

    def __len__(self):
        return len(self.items)

    def __getitem__(self, pos):
        return self.items[pos]

    def __setitem__(self, pos, value):
        self.items[pos] = value

    def __contains__(self, item):
        return item in self.items
```

Without it debugging sucks.

Add:

def __repr__(self):

# Exercise 4 — `RateLimiter`

Actually good. Just one improvement.

Your code:

```python
raise Exception(...)
```

❌ Never raise generic `Exception`.

Create **specific exception**.

---

### Better

```python
class RateLimitExceeded(Exception):
    pass
```

Then:

```python
class RateLimiter:

    def __init__(self, max_calls):
        self.max_calls = max_calls
        self.curr_calls = 0

    def __call__(self):
        if self.curr_calls >= self.max_calls:
            raise RateLimitExceeded("Rate limit exceeded")

        self.curr_calls += 1
```
