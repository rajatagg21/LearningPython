# 4. Method Resolution Order (MRO)

Critical for multiple inheritance.

Topics:

* inheritance basics
* multiple inheritance
* diamond problem
* C3 linearization
* `.mro()`
* `__mro__`
* `super()`

Also understand:

```
why MRO must be monotonic
```
Good. This topic separates **people who actually understand Python OOP** from people who just copy code.

If you don't understand MRO, **multiple inheritance will break your production systems** and debugging will become hell.

I'll give you **only the essential mental model**.

---

# 1. Inheritance Basics

Single inheritance first.

```python
class A:
    def greet(self):
        print("A")

class B(A):
    pass

b = B()
b.greet()
```

Lookup:

```
B instance
↓
B class
↓
A class
```

So output:

```
A
```

You already know this from **attribute lookup**.

The difference now is:

```
multiple parents
```

---

# 2. Multiple Inheritance

Example:

```python
class A:
    def greet(self):
        print("A")

class B:
    def greet(self):
        print("B")

class C(A, B):
    pass

c = C()
c.greet()
```

Which `greet` should Python call?

Answer:

```
A.greet
```

Because **inheritance order matters**.

```
class C(A, B)
```

Search order:

```
C → A → B
```

---

You can verify:

```python
print(C.mro())
```

Output:

```
[C, A, B, object]
```

---

# 3. `.mro()` and `__mro__`

Both show the same thing.

Example:

```python
class A: pass
class B(A): pass
class C(B): pass

print(C.mro())
print(C.__mro__)
```

Output:

```
[C, B, A, object]
```

Important:

```
Python always searches attributes using MRO order
```

---

# 4. The Diamond Problem

Now things get dangerous.

```
        A
       / \
      B   C
       \ /
        D
```

Code:

```python
class A:
    def greet(self):
        print("A")

class B(A):
    pass

class C(A):
    pass

class D(B, C):
    pass

d = D()
d.greet()
```

Which `A` should be used?

This is the **diamond problem**.

Older languages (C++) had ambiguity.

Python solves this using **C3 Linearization**.

---

Check MRO:

```python
print(D.mro())
```

Result:

```
[D, B, C, A, object]
```

So search path:

```
D
B
C
A
object
```

---

# 5. Why MRO Must Be Monotonic

This is the **most important rule**.

Monotonic means:

```
child class cannot change the ordering constraints of parents
```

Example.

Parent order:

```
A before B
```

Child cannot reverse it.

Bad example:

```python
class A: pass
class B: pass

class C(A, B): pass
class D(B, A): pass

class E(C, D): pass
```

Python throws:

```
TypeError: Cannot create a consistent method resolution order
```

Why?

Because:

```
C requires A before B
D requires B before A
```

Impossible ordering.

So Python refuses.

This is **monotonic MRO**.

---

# 6. C3 Linearization (Conceptual Only)

Don't memorize the algorithm. Understand the rules.

C3 guarantees:

```
1. Child first
2. Preserve parent order
3. Preserve local precedence order
4. No contradictions
```

Example:

```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass
```

Python merges:

```
D
B
C
A
object
```

# 8. `super()`

Most developers misuse `super()`.

They think it means:

```
call parent
```

Wrong.

It means:

```
call next class in MRO
```

Example:

```python
class A:
    def greet(self):
        print("A")

class B(A):
    def greet(self):
        print("B")
        super().greet()

class C(B):
    def greet(self):
        print("C")
        super().greet()

c = C()
c.greet()
```

Output:

```
C
B
A
```

Call chain:

```
C → B → A
```

Because MRO:

```
[C, B, A, object]
```

---

# 9. `super()` in Diamond Inheritance

Now watch carefully.

```python
class A:
    def greet(self):
        print("A")

class B(A):
    def greet(self):
        print("B")
        super().greet()

class C(A):
    def greet(self):
        print("C")
        super().greet()

class D(B, C):
    def greet(self):
        print("D")
        super().greet()

d = D()
d.greet()
```

MRO:

```
[D, B, C, A, object]
```

Execution:

```
D
B
C
A
```

Notice something important:

```
A runs only once
```

This is the **entire reason Python uses C3**.

---

# 10. Real Production Rule

If you use multiple inheritance:

### ALWAYS use `super()`

Wrong:

```python
A.greet(self)
```

Correct:

```python
super().greet()
```

Otherwise you break cooperative inheritance.

Framework code relies on this.

# Production Insight (Important)

Many frameworks depend on **cooperative inheritance**.

Example:

Bad code:

```python
class FileLogger(Logger):
    def log(self):
        print("File")
        Logger.log(self)
```

This **breaks the chain**.

Now:

```
NetworkLogger.log never runs
```

Always use:

```
super()
```

Never directly call parent.

# One MRO Trap (Very Important)

Consider this:

```python
class A:
    def f(self):
        print("A")

class B(A):
    def f(self):
        print("B")
        super().f()

class C(A):
    def f(self):
        print("C")

class D(B, C):
    pass

d = D()
d.f()
```

Output:

```
B
C
```

Why?

Because:

```
C.f does NOT call super()
```

So the chain **stops**.

This breaks cooperative inheritance.

Framework authors **hate this mistake**.
