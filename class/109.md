# 9. Memory Layout of Objects

Important for performance and debugging.

Topics:

* object memory
* instance dictionaries
* `__slots__`
* attribute storage
* memory optimization

Example:

```
class A:
    __slots__ = ['x']
```

---

You’re entering **Python internals territory** now. Good. Most Python devs never understand this and write memory-bloated garbage.

Let’s make this **painfully clear**.

---

# 1. Python Object Memory Model

Every Python object has **two layers of memory**.

### Layer 1 — Object Header

Stored for **every object**.

Contains:

* reference count
* pointer to object type
* flags / GC metadata

Conceptually:

```
+-------------------+
| ref_count         |
| type_pointer      |
| GC flags          |
+-------------------+
| object data       |
+-------------------+
```

Even an empty object costs memory.

Example:

```python
class A:
    pass

a = A()
```

Memory exists even if `A` has no attributes.

---

# 2. Instance Dictionary (`__dict__`)

By default Python stores attributes in a **dictionary per object**.

Example:

```python
class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age
```

Internally:

```
user object
    |
    +----> __dict__
            |
            +--- "name" -> "Rajat"
            +--- "age"  -> 30
```

Let's prove it.

```python
u = User("Rajat", 30)

print(u.__dict__)
```

Output

```
{'name': 'Rajat', 'age': 30}
```

This is **slow and memory heavy** because:

A dictionary stores

```
hash
key
value
pointer
```

per attribute.

---

# 3. Memory Cost of `__dict__`

Example:

```python
class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age
```

Now create many objects.

```python
users = [User("A", 20) for _ in range(1_000_000)]
```

Each object contains

```
object header
pointer to __dict__
dict object
dict entries
```

Huge waste.

Production systems handling **millions of objects** suffer here.

Examples:

* ORMs
* AST trees
* graph nodes
* ML feature objects
* simulation systems

---

# 4. `__slots__`

`__slots__` removes the instance dictionary.

Example:

```
class User:
    __slots__ = ["name", "age"]

    def __init__(self, name, age):
        self.name = name
        self.age = age
```

Now object layout becomes:

```
User object
  |
  +-- name (slot)
  +-- age  (slot)
```

No dictionary.

Attributes stored in **fixed memory offsets**.

Much faster.

---

# 5. Verify the Difference

### Without slots

```python
class A:
    def __init__(self):
        self.x = 1
```

```
a = A()
print(a.__dict__)
```

Output

```
{'x': 1}
```

---

### With slots

```python
class B:
    __slots__ = ["x"]

    def __init__(self):
        self.x = 1
```

```
b = B()
print(b.__dict__)
```

Result

```
AttributeError
```

Because **there is no dictionary**.

# 6. Memory Comparison

Example experiment.

```python
import sys

class A:
    def __init__(self):
        self.x = 1
        self.y = 2


class B:
    __slots__ = ["x", "y"]

    def __init__(self):
        self.x = 1
        self.y = 2


a = A()
b = B()

print(sys.getsizeof(a))
print(sys.getsizeof(b))
```

Typical results:

```
A → ~56 bytes
B → ~40 bytes
```

But real savings appear with **millions of objects**.

# 7. Attribute Lookup

### Normal class

Lookup path:

```
obj.attr

1 instance.__dict__
2 class.__dict__
3 parent classes
```

---

### Slots class

Lookup path:

```
obj.attr

1 slot offset lookup
2 class
3 parent classes
```

Slots skip the dictionary.

Faster.

---

# 8. Downsides of `__slots__`

This is where most juniors screw up.

### 1️⃣ Cannot add attributes dynamically

```
obj.new_attr = 10
```

Fails.

---

### 2️⃣ No `__dict__`

Some frameworks depend on it.

Example:

* Django ORM
* serialization
* debugging tools

---

### 3️⃣ Inheritance complexity

Example:

```
class A:
    __slots__ = ["x"]

class B(A):
    __slots__ = ["y"]
```

If you forget slots in subclass:

```
class B(A):
    pass
```

Python silently re-introduces `__dict__`.

Memory benefit gone.

---

# 9. When Production Systems Use `__slots__`

Used in:

### Compilers

Example:

* AST nodes

Millions of small objects.

---

### Networking libraries

Packets / message objects.

---

### Simulation engines

Physics / trading / gaming.

---

### ML preprocessing pipelines

Large intermediate objects.

# 10. Advanced Detail (Important)

Slots create **descriptors**.

Internally:

```
User.name → member_descriptor
```

Example:

```python
class User:
    __slots__ = ["name"]

print(User.name)
```

Output:

```
<member 'name' of 'User' objects>
```

This descriptor manages the slot storage.

---

# 11. Allow `__dict__` with Slots

Sometimes needed.

```
class User:
    __slots__ = ["name", "__dict__"]
```

Now:

```
fixed slots + dynamic attributes
```

Example:

```
u.extra = 10
```

Works.

---

# 12. Slots with Weak References

Needed for caches.

```
class A:
    __slots__ = ['x', '__weakref__']
```

Otherwise weakrefs fail.

# 13. Visual Comparison

```

### Slot Object

```

# Production Takeaway

Use `__slots__` when:

✔ many small objects
✔ attributes fixed
✔ performance critical

Avoid when:

✘ frameworks need `__dict__`
✘ dynamic attributes required
✘ rapid prototyping

If you want to track memory accurately in Python, you have to move beyond `sys.getsizeof` because it simply doesn't "see" the full picture.

Here are the three most professional ways to profile memory, depending on whether you want to measure **objects**, **lines of code**, or **the whole system**.

---

### 1. `Pympler`: The "Deep" Object Tracker

As you've seen, Python objects are often containers pointing to other containers. `Pympler` is a library specifically designed to follow those pointers and give you the "real" size.

```python
from pympler import asizeof

# This will correctly show that A is much larger than B
# because it traverses into the hidden __dict__
print(f"Real size of A: {asizeof.asizeof(a[0])} bytes")
print(f"Real size of B: {asizeof.asizeof(b[0])} bytes")

```

### 2. `tracemalloc`: The Standard Library Way

Since Python 3.4, the `tracemalloc` module is built-in. It allows you to take "snapshots" of memory at different points in your code and compare them to see exactly where memory grew.

```python
import tracemalloc

tracemalloc.start()

# --- Run your code here ---
snapshot = tracemalloc.take_snapshot()
top_stats = snapshot.statistics('lineno')

for stat in top_stats[:3]:
    print(stat)

```

**Why use this?** It tells you which **line of code** allocated the memory, which is a lifesaver for finding leaks in large projects.

### 3. `memory_profiler`: Line-by-Line Analysis

If you want a "heat map" of your function to see which specific line spikes your RAM, this is the best tool. It adds a decorator to your functions.

```python
# Usage: python -m memory_profiler your_script.py
from memory_profiler import profile

@profile
def my_func():
    a = [A() for _ in range(100000)]
    b = [B() for _ in range(100000)]
    return a, b

```

---

### Comparison of Tools

| Tool | Best For... | Accuracy |
| --- | --- | --- |
| **`sys.getsizeof`** | Simple primitives (integers, strings). | Low (Shallow) |
| **`Pympler`** | Understanding the true cost of complex objects. | High (Deep) |
| **`tracemalloc`** | Finding where memory is leaking in a script. | High (System-level) |
| **`memory_profiler`** | Line-by-line breakdown of a specific function. | High (Visual) |

### Pro-Tip: The "Valgrind" of Python

If you are doing heavy data science or C-extensions, check out **Memray**. It is a modern memory profiler by Bloomberg that can track memory allocations in both Python and C/C++ code simultaneously, generating beautiful HTML flame graphs.

# Correct Answer-1 — Memory Comparison

Key fixes:

* Measure **whole list**, not each object.
* Avoid **double memory contamination**.
* Force **GC cleanup**.

```python
import gc
from pympler import asizeof


class A:
    def __init__(self):
        self.x = 1
        self.y = 2


class B:
    __slots__ = ['x', 'y']

    def __init__(self):
        self.x = 1
        self.y = 2


OBS = 1_000_000

# Measure normal class
a = [A() for _ in range(OBS)]
mem_a = asizeof.asizeof(a)

print(f"Memory with __dict__: {mem_a / (1024*1024):.2f} MB")

del a
gc.collect()

# Measure slots class
b = [B() for _ in range(OBS)]
mem_b = asizeof.asizeof(b)

print(f"Memory with __slots__: {mem_b / (1024*1024):.2f} MB")

print(f"Memory saved: {(mem_a - mem_b)/(1024*1024):.2f} MB")
```

# Correct Answer-2 — Point Class

Fixes:

* Use `math.hypot`
* Demonstrate absence of `__dict__`

```python
import math


class Point:
    __slots__ = ['x', 'y']

    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

    def distance_from_origin(self) -> float:
        return math.hypot(self.x, self.y)


p = Point(3, 4)

print(p.distance_from_origin())   # 5.0
print(Point.__dict__)

try:
    print(p.__dict__)
except AttributeError:
    print("Instance has no __dict__ because of __slots__")
```

# Correct Answer-3 — Vector3D

Fixes:

* Correct **dot product**
* Slight math improvements

```python
import math


class Vector3D:
    __slots__ = ['x', 'y', 'z']

    def __init__(self, x: float, y: float, z: float):
        self.x = x
        self.y = y
        self.z = z

    def magnitude(self) -> float:
        return math.sqrt(
            self.x*self.x +
            self.y*self.y +
            self.z*self.z
        )

    def dot(self, other: "Vector3D") -> float:
        return (
            self.x * other.x +
            self.y * other.y +
            self.z * other.z
        )


v1 = Vector3D(1, 2, 3)
v2 = Vector3D(4, 5, 6)

print(v1.magnitude())
print(v1.dot(v2))
```

# Correct Answer-4 — StockTick Memory Optimization

Fixes:

* Measure **list once**
* Use realistic types
* Avoid per-object `asizeof`

```python
import gc
from pympler import asizeof


class StockTick:
    def __init__(self, symbol: str, price: float, timestamp: int, volume: int):
        self.symbol = symbol
        self.price = price
        self.timestamp = timestamp
        self.volume = volume


class StockTickSlots:
    __slots__ = ['symbol', 'price', 'timestamp', 'volume']

    def __init__(self, symbol: str, price: float, timestamp: int, volume: int):
        self.symbol = symbol
        self.price = price
        self.timestamp = timestamp
        self.volume = volume


OBS = 1_000_000

ticks = [
    StockTick("AAPL", 180.0, 1700000000, 100)
    for _ in range(OBS)
]

mem_dict = asizeof.asizeof(ticks)

print(f"Memory with dict: {mem_dict/(1024*1024):.2f} MB")

del ticks
gc.collect()

ticks_slots = [
    StockTickSlots("AAPL", 180.0, 1700000000, 100)
    for _ in range(OBS)
]

mem_slots = asizeof.asizeof(ticks_slots)

print(f"Memory with slots: {mem_slots/(1024*1024):.2f} MB")

print(f"Memory saved: {(mem_dict-mem_slots)/(1024*1024):.2f} MB")
```

# One More Production Improvement (Very Important)

For **large graphs**, store **IDs instead of objects**.

Better memory locality.

```python
class GraphNode:
    __slots__ = ['id', 'neighbors']

    def __init__(self, node_id):
        self.id = node_id
        self.neighbors = []   # store node ids
```

Example:

```
neighbors = [12, 45, 98]
```

Instead of storing object references.

Used in:

* graph engines
* compilers
* ML pipelines
