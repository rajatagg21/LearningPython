# 10. Attribute Access Hooks

Powerful feature for frameworks.

Topics:

```
__getattribute__
__getattr__
__setattr__
__delattr__
```

Use cases:

* lazy loading
* validation
* proxy objects
* logging access

---

Good. This is one of the **most misunderstood parts of Python's object model**. If you understand this properly, you understand **how ORMs, proxies, lazy loaders, and half of Python frameworks work**.

I'll keep it **tight and brutal**. No fluff.

---

# 1. The Attribute Lookup Pipeline (You MUST know this)

When you do:

```python
obj.attr
```

Python internally runs:

```
obj.__getattribute__("attr")
```

**Always.**

Flow:

```
1. __getattribute__ is called
2. If attribute exists → return it
3. If not found → __getattr__ is called
4. If still not found → AttributeError
```

Pipeline:

```
obj.attr
   ↓
__getattribute__()
   ↓
(found?) ── yes → return
   ↓ no
__getattr__()
   ↓
(found?) ── yes → return
   ↓ no
AttributeError
```

Memorize this.

---

# 2. `__getattribute__`

### Definition

Intercepts **every attribute access**.

```python
class A:
    def __getattribute__(self, name):
        print("Accessing:", name)
        return super().__getattribute__(name)
```

Usage:

```python
a = A()
a.x
```

Output

```
Accessing: x
AttributeError
```

Because `x` doesn't exist.

---

### ⚠ The biggest mistake

If you do this:

```python
class A:
    def __getattribute__(self, name):
        return self.name
```

You created **infinite recursion**.

Because:

```
self.name
     ↓
__getattribute__
     ↓
self.name
     ↓
loop forever
```

Correct approach:

```
super().__getattribute__()
```

Always.

---

### Production Example: Access Logging

Used in **debug frameworks, tracing, ORMs**.

```python
class AccessLogger:

    def __init__(self):
        self.name = "Rajat"
        self.age = 25

    def __getattribute__(self, name):
        print(f"[LOG] accessing {name}")
        return super().__getattribute__(name)
```

Usage

```python
obj = AccessLogger()
print(obj.name)
```

Output

```
[LOG] accessing name
Rajat
```

# 3. `__getattr__`

This is a **fallback**.

Called **only if attribute does NOT exist**.

Example:

```python
class A:

    def __getattr__(self, name):
        return f"{name} not found"
```

Usage

```python
a = A()

print(a.x)
```

Output

```
x not found
```

---

### Production Example: Lazy Attributes

Frameworks use this for **lazy loading expensive data**.

```python
class User:

    def __init__(self):
        self.name = "Rajat"

    def __getattr__(self, name):

        if name == "profile":
            print("Loading profile from DB...")
            value = {"age": 25}

            setattr(self, name, value)
            return value

        raise AttributeError
```

Usage

```python
u = User()

u.profile
u.profile
```

Output

```
Loading profile from DB...
```

Second access is **cached**.

This is **lazy loading**.

Used heavily in:

* Django ORM
* SQLAlchemy
* caching frameworks

# 4. `__setattr__`

Intercepts **every attribute assignment**.

```
obj.x = 10
```

calls

```
__setattr__(obj, "x", 10)
```

Example:

```python
class A:

    def __setattr__(self, name, value):
        print("Setting", name, value)
        super().__setattr__(name, value)
```

Usage

```python
a = A()
a.x = 10
```

Output

```
Setting x 10
```

---

### ⚠ Same recursion problem

Wrong:

```python
self.name = value
```

Correct:

```
super().__setattr__()
```

---

### Production Example: Validation Layer

Used in **pydantic / ORM models**.

```python
class User:

    def __setattr__(self, name, value):

        if name == "age" and value < 0:
            raise ValueError("Invalid age")

        super().__setattr__(name, value)
```

Usage

```python
u = User()
u.age = 25
u.age = -1
```

Output

```
ValueError
```

# 6. Production Pattern: Proxy Objects

Extremely important.

Proxy objects **forward attribute access**.

Example:

```python
class Proxy:

    def __init__(self, obj):
        super().__setattr__("obj", obj)

    def __getattr__(self, name):
        return getattr(self.obj, name)

    def __setattr__(self, name, value):
        setattr(self.obj, name, value)
```

Usage

```python
class User:
    def __init__(self):
        self.name = "Rajat"

u = User()
p = Proxy(u)

print(p.name)
```

Output

```
Rajat
```

This pattern powers:

* database session objects
* lazy objects
* RPC clients
* caching wrappers

---

# 7. Production Pattern: Read Only Object

```python
class Config:

    def __init__(self):
        super().__setattr__("version", "1.0")

    def __setattr__(self, name, value):
        raise AttributeError("Config is read only")
```

Usage

```python
c = Config()
c.version = "2"
```

Output

```
AttributeError
```

---

# 8. The Most Important Rule

Use this mental model:

```
__getattribute__ → intercept EVERYTHING

__getattr__ → fallback only

__setattr__ → intercept assignments

__delattr__ → intercept deletes
```

# 1. Lazy API Client

Goal:

```python
client.users.get()
client.posts.create()
```

### Implementation

```python
class Endpoint:
    def __init__(self, name):
        self.name = name

    def get(self):
        return f"GET request to /{self.name}"

    def create(self):
        return f"POST request to /{self.name}"


class APIClient:

    def __getattr__(self, name):
        # dynamically create endpoint
        return Endpoint(name)


client = APIClient()

print(client.users.get())
print(client.posts.create())
```

### Output

```
GET request to /users
POST request to /posts
```

Why this works:

```
client.users
        ↓
__getattr__("users")
        ↓
Endpoint("users")
```

This pattern is used in **dynamic API SDKs**.

# 2. Field Validation with `__setattr__`

Goal:

```
price > 0
quantity >= 0
```

### Implementation

```python
class Product:

    def __setattr__(self, name, value):

        if name == "price" and value <= 0:
            raise ValueError("Price must be positive")

        if name == "quantity" and value < 0:
            raise ValueError("Quantity cannot be negative")

        super().__setattr__(name, value)


p = Product()

p.price = 100
p.quantity = 10

print(p.price, p.quantity)

# invalid
p.quantity = -5
```

### Output

```
100 10
ValueError: Quantity cannot be negative
```

This pattern is used in:

* validation layers
* ORMs
* pydantic-like frameworks

# 3. Access Logger Proxy

Goal:

```
proxy = LoggerProxy(obj)
proxy.name
```

Output:

```
[ACCESS] name
```

### Implementation

```python
class LoggerProxy:

    def __init__(self, obj):
        super().__setattr__("_obj", obj)

    def __getattr__(self, name):
        print(f"[ACCESS] {name}")
        return getattr(self._obj, name)


class User:
    def __init__(self):
        self.name = "Rajat"
        self.age = 25


u = User()
proxy = LoggerProxy(u)

print(proxy.name)
print(proxy.age)
```

### Output

```
[ACCESS] name
Rajat
[ACCESS] age
25
```

Explanation:

```
proxy.name
      ↓
__getattr__
      ↓
getattr(real_object)
```

# 4. Frozen Object

Goal:

```
cannot modify attributes
```

### Implementation

```python
class FrozenDict:

    def __init__(self, **kwargs):
        for k, v in kwargs.items():
            super().__setattr__(k, v)

    def __setattr__(self, name, value):
        raise AttributeError("Object is frozen")

    def __delattr__(self, name):
        raise AttributeError("Object is frozen")


f = FrozenDict(a=10, b=20)

print(f.a)

f.a = 30
```

### Output

```
10
AttributeError: Object is frozen
```

Used in:

* configuration objects
* immutable settings
* caching layers

# 5. Lazy File Loader

Goal:

```
file.content
```

Load file **only on first access**.

### Implementation

```python
class LazyFile:

    def __init__(self, path):
        self.path = path

    def __getattr__(self, name):

        if name == "content":
            print("Loading file...")
            with open(self.path) as f:
                data = f.read()

            setattr(self, "content", data)
            return data

        raise AttributeError


f = LazyFile("test.txt")

print(f.content)
print(f.content)
```

### Output

```
Loading file...
<file content here>
<file content here>
```

Important behavior:

First call:

```
content not found
      ↓
__getattr__
      ↓
load file
      ↓
setattr(self,"content",data)
```

Second call:

```
content exists
      ↓
direct access
```

No file read.

This pattern is used in:

* lazy DB relations
* caching systems
* expensive computation

# Final Mental Model (Burn this into memory)

```
obj.attr
   ↓
__getattribute__  (always)
   ↓
attribute exists? → yes → return
   ↓
__getattr__       (fallback)
   ↓
return value or raise error
```

Assignments:

```
obj.attr = value
     ↓
__setattr__
```

Deletion:

```
del obj.attr
      ↓
__delattr__
```
