# 1. What problem does this solve?

Without **Abstract Base Classes (ABC)**:

```python
class MySQLDB:
    def connect(self): ...
    def query(self): ...

class MongoDB:
    def connect(self): ...
    def query(self): ...
```

Looks fine… until someone does:

```python
class RedisDB:
    def connect(self): ...
    # forgot query()
```

You won’t know until runtime → production bug.

👉 ABC = **fail fast + enforce contract**

---

# 2. Core Concepts

## `abc` module

Gives you tools to define *interfaces*.

---

## `ABC` (Abstract Base Class)

Base class that cannot be instantiated if it has abstract methods.

```python
from abc import ABC
```

---

## `@abstractmethod`

Forces child classes to implement method.

---

# 3. Minimal Example (Don’t overcomplicate)

```python
from abc import ABC, abstractmethod

class Database(ABC):

    @abstractmethod
    def connect(self):
        pass

    @abstractmethod
    def query(self, sql):
        pass
```

Now:

```python
class MySQL(Database):
    def connect(self):
        print("MySQL connected")

    def query(self, sql):
        return f"Executing {sql} in MySQL"
```

Works.

---

### Bad implementation:

```python
class Redis(Database):
    def connect(self):
        print("Redis connected")
```

💥 Error:

```
TypeError: Can't instantiate abstract class Redis with abstract method query
```

👉 This is EXACTLY what you want in production.

# 4. Production Thinking

## Use case 1: Interface design

You’re building a system where multiple implementations will exist.

Example:

* Payment gateways
* Notification systems
* ML model backends

---

### Example: Notification System

```python
class Notifier(ABC):

    @abstractmethod
    def send(self, message):
        pass
```

Implementations:

```python
class EmailNotifier(Notifier):
    def send(self, message):
        print(f"Email: {message}")

class SMSNotifier(Notifier):
    def send(self, message):
        print(f"SMS: {message}")
```

---

### Usage (clean system):

```python
def notify_user(notifier: Notifier):
    notifier.send("Hello")
```

👉 You don’t care which notifier it is.
👉 That’s abstraction. That’s scalable design.

---

## Use case 2: Plugin Architecture

This is where ABC actually matters.

You define a contract → external developers implement it.

---

### Core system:

```python
class Plugin(ABC):

    @abstractmethod
    def run(self, data):
        pass
```

---

### External plugin:

```python
class UpperCasePlugin(Plugin):
    def run(self, data):
        return data.upper()
```

---

### Engine:

```python
def execute(plugin: Plugin, data):
    return plugin.run(data)
```

---

👉 You can now drop in new plugins without touching core system.

That’s how real systems scale.

# 5. Subtle but IMPORTANT things

## 1. You CAN have concrete methods inside ABC

```python
class Base(ABC):

    @abstractmethod
    def process(self):
        pass

    def log(self):
        print("Logging...")
```

---

## 2. Abstract methods can have implementation (rare but useful)

```python
class Base(ABC):

    @abstractmethod
    def process(self):
        print("Common preprocessing")
```

Child must override, but can call `super()`.

---

## 3. Multiple inheritance works

```python
class A(ABC):
    @abstractmethod
    def x(self): pass

class B(A):
    def x(self): print("done")
```

---

## 4. Don’t overuse ABC

If you’re not enforcing a contract → don’t use it.

Bad engineers:

* create ABC for everything
* zero real abstraction
* fake “clean code”

---

# 6. When to use vs NOT use

## Use ABC when:

✔ Multiple interchangeable implementations
✔ You expect extension (plugins, adapters)
✔ You want strict contracts

---

## DON’T use ABC when:

❌ Single implementation
❌ Internal script
❌ You’re guessing future extensibility

# ✅ 1. Payment Gateway

```python
from abc import ABC, abstractmethod

class PaymentGateway(ABC):
    @abstractmethod
    def pay(self, amount):
        pass

    @abstractmethod
    def refund(self, amount):
        pass


class Razorpay(PaymentGateway):
    def pay(self, amount):
        print(f"Razorpay paid ₹{amount}")

    def refund(self, amount):
        print(f"Razorpay refunded ₹{amount}")


class Stripe(PaymentGateway):
    def pay(self, amount):
        print(f"Stripe paid ${amount}")

    def refund(self, amount):
        print(f"Stripe refunded ${amount}")


def process_payment(gateway: PaymentGateway):
    gateway.pay(100)
    gateway.refund(50)


# Output
process_payment(Razorpay())
process_payment(Stripe())
```

### Output:

```
Razorpay paid ₹100
Razorpay refunded ₹50
Stripe paid $100
Stripe refunded $50
```

# ✅ 2. ML Model Interface (important for you)

```python
class Model(ABC):
    @abstractmethod
    def load(self):
        pass

    @abstractmethod
    def predict(self, text):
        pass


class DummyModel(Model):
    def load(self):
        print("Dummy model loaded")

    def predict(self, text):
        return "constant_output"


class MiniLMModel(Model):
    def load(self):
        print("MiniLM model loaded")

    def predict(self, text):
        return f"embedding_for: {text}"


def run_inference(model: Model, text):
    model.load()
    result = model.predict(text)
    print(result)


# Output
run_inference(DummyModel(), "hello")
run_inference(MiniLMModel(), "hello")
```

### Output:

```
Dummy model loaded
constant_output
MiniLM model loaded
embedding_for: hello
```

# ✅ 3. Logging System (plugin style)

```python
class Logger(ABC):
    @abstractmethod
    def log(self, message):
        pass


class FileLogger(Logger):
    def log(self, message):
        print(f"[FILE] {message}")


class DatabaseLogger(Logger):
    def log(self, message):
        print(f"[DB] {message}")


class ConsoleLogger(Logger):
    def log(self, message):
        print(f"[CONSOLE] {message}")


def log_all(loggers: list[Logger], msg):
    for logger in loggers:
        logger.log(msg)


# Output
loggers = [FileLogger(), DatabaseLogger(), ConsoleLogger()]
log_all(loggers, "System started")
```

### Output:

```
[FILE] System started
[DB] System started
[CONSOLE] System started
```

# ✅ 4. Notification Router (Improved version of yours)

Now this is **production-grade version** (with failure handling + routing).

```python
class Notifier(ABC):
    @abstractmethod
    def notify(self, text):
        pass


class EmailNotifier(Notifier):
    def notify(self, text):
        print(f"[EMAIL] {text}")


class SMSNotifier(Notifier):
    def notify(self, text):
        print(f"[SMS] {text}")


class PushNotifier(Notifier):
    def notify(self, text):
        print(f"[PUSH] {text}")
```

---

## Manager (with routing + retry + failure isolation)

```python
class NotificationManager:
    def __init__(self, notifiers: dict[str, Notifier]):
        self.notifiers = notifiers

    def _safe_notify(self, notifier, text, retries=2):
        for attempt in range(retries + 1):
            try:
                notifier.notify(text)
                return
            except Exception as e:
                print(f"Error: {e}, attempt={attempt}")
        print("Failed after retries")

    def notify(self, text, channel="all"):
        if channel == "all":
            for notifier in self.notifiers.values():
                self._safe_notify(notifier, text)
        else:
            notifier = self.notifiers.get(channel)
            if notifier:
                self._safe_notify(notifier, text)
            else:
                print("Invalid channel")
```

---

## Usage

```python
notifiers = {
    "email": EmailNotifier(),
    "sms": SMSNotifier(),
    "push": PushNotifier()
}

nm = NotificationManager(notifiers)

nm.notify("Hello World", "email")
nm.notify("Hello Everyone", "all")
nm.notify("Oops", "invalid")
```

---

### Output:

```
[EMAIL] Hello World
[EMAIL] Hello Everyone
[SMS] Hello Everyone
[PUSH] Hello Everyone
Invalid channel
```
