# 6. Method Types

Different method behaviors.

Topics:

* instance methods
* class methods
* static methods
* bound vs unbound methods
* method binding mechanics

Understand internally:

```
function -> descriptor -> bound method
```

Good. This is **core Python object model knowledge**. If you don’t understand this, you don’t actually understand Python classes — you’re just memorizing syntax.

Let’s build this **from the internals outward**.

---

# 1. The Truth: Methods Are Just Functions

In Python, a method is **just a function stored inside a class namespace**.

Example:

```python
class User:
    def greet(self):
        print("Hello")
```

Check what `greet` actually is:

```python
print(type(User.greet))
```

Output:

```
<class 'function'>
```

So inside the class:

```
User.__dict__['greet'] -> function object
```

Not a method.

Just a **function**.

---

# 2. Then What Is a Method?

A **method appears when a function is accessed through an instance.**

Example:

```python
u = User()

print(type(u.greet))
```

Output:

```
<class 'method'>
```

So:

```
User.greet -> function
u.greet    -> bound method
```

Why?

Because **descriptors**.

---

# 3. The Real Mechanism

Python does this internally:

```
function -> descriptor -> bound method
```

Functions implement the **descriptor protocol**.

Internally:

```
function.__get__(instance, owner)
```

Example:

```python
class User:
    def greet(self):
        print("hello")

u = User()

print(User.greet)        # function
print(User.greet.__get__(u, User))  # manual binding
```

Output:

```
<function User.greet>
<bound method User.greet of <User object>>
```

Equivalent to:

```
u.greet
```

So Python effectively does:

```
User.greet.__get__(u, User)
```

This returns a **bound method**.

---

# 4. What Is a Bound Method?

A **bound method = function + instance**

It stores two things:

```
bound_method.__self__  -> instance
bound_method.__func__  -> original function
```

Example:

```python
u = User()

m = u.greet

print(m.__self__)
print(m.__func__)
```

Output:

```
<User object>
<function User.greet>
```

Equivalent call:

```
m()
```

Python executes internally:

```
User.greet(u)
```

The instance is **automatically injected as first argument**.

---

# 5. Instance Methods

Definition:

```
method bound to instance
```

Example:

```python
class Order:
    def total(self, price, qty):
        return price * qty
```

Usage:

```
o = Order()
o.total(10, 5)
```

Internally:

```
Order.total(o, 10, 5)
```

Production example:

```python
class DatabaseConnection:

    def connect(self):
        print(f"connecting {self}")
```

Each instance has its **own state**.

---

# 6. Class Methods

Class methods are bound to **the class**, not the instance.

Created using:

```
@classmethod
```

Example:

```python
class User:

    count = 0

    def __init__(self):
        User.count += 1

    @classmethod
    def get_count(cls):
        return cls.count
```

Usage:

```
User.get_count()
```

or

```
u = User()
u.get_count()
```

Both work.

Why?

Because classmethod descriptor binds to **class**.

Internally:

```
User.get_count.__get__(None, User)
```

Returns:

```
bound method -> (function + class)
```

So:

```
cls = User
```

---

### Production Uses

Factories.

Example:

```python
class User:

    def __init__(self, name):
        self.name = name

    @classmethod
    def from_dict(cls, data):
        return cls(data["name"])
```

Used everywhere:

```
ORM
config loaders
deserialization
model factories
```

---

# 7. Static Methods

Static methods are **just functions placed in class namespace**.

No binding.

Example:

```python
class MathUtils:

    @staticmethod
    def add(a, b):
        return a + b
```

Usage:

```
MathUtils.add(1,2)
```

or

```
MathUtils().add(1,2)
```

Both work.

But internally **nothing is injected**.

It is literally:

```
function(a, b)
```

---

# 8. Why Staticmethod Exists

Without it:

```
class Math:
    def add(a, b):
        return a+b
```

Now Python will try:

```
instance.add(self, a, b)
```

Which breaks.

`@staticmethod` disables binding.

---

# 9. Internal Representation

Let’s inspect.

```
class A:

    def inst(self): pass

    @classmethod
    def cls(cls): pass

    @staticmethod
    def stat(): pass
```

Now:

```
print(A.__dict__['inst'])
print(A.__dict__['cls'])
print(A.__dict__['stat'])
```

Output:

```
function
classmethod object
staticmethod object
```

So:

```
inst -> function descriptor
cls  -> classmethod descriptor
stat -> staticmethod descriptor
```

Descriptors again.

---

# 10. Descriptor Behavior

### instance method

```
function.__get__(instance, owner)
```

returns:

```
bound method
```

---

### classmethod

```
classmethod.__get__(instance, owner)
```

returns:

```
function bound to class
```

---

### staticmethod

```
staticmethod.__get__(instance, owner)
```

returns:

```
raw function
```

No binding.

---

# 11. Bound vs Unbound Methods

Python 2 had **unbound methods**.

Python 3 simplified it.

Now:

```
User.greet -> function
u.greet    -> bound method
```

So unbound methods **no longer exist**.

---

# 12. Real Production Rule

Use:

### instance method

When you need **instance state**

```
self
```

Example:

```
user.save()
order.calculate_total()
model.predict()
```

---

### classmethod

When you need **class-level logic**

Factories.

```
Model.from_pretrained()
Config.from_json()
User.from_db()
```

---

### staticmethod

When function **logically belongs to class but uses nothing**

Example:

```
Validator.is_email()
MathUtils.clamp()
Tokenizer.normalize()
```

But many engineers avoid staticmethod and just use module functions.

---

# 13. Performance Note

Bound method creation happens **every attribute access**.

```
u.method
```

creates new bound method object.

Which is why this pattern is faster in loops:

```
m = u.method
for _ in range(1000000):
    m()
```

---

# 14. Visual Mental Model

When you write:

```
u.method()
```

Python does:

```
func = User.__dict__['method']
bound = func.__get__(u, User)
bound()
```

Which becomes:

```
func(u)
```

```python
type(A.f)  -> function
type(a.f)  -> method
```

### Why

```
A.f -> raw function
a.f -> function.__get__(a, A) -> bound method
```

# Exercise 2

### Implement manual binding

Goal: simulate `instance.method`.

```python
def bind(func, instance):
    def bound(*args, **kwargs):
        return func(instance, *args, **kwargs)
    return bound
```

Usage:

```python
class A:
    def f(self, x):
        print(self, x)

a = A()

m = bind(A.f, a)
m(10)
```

Equivalent to:

```
a.f(10)
```

What you just created is a **manual bound method**.

# Exercise 3

### Implement `@classmethod`

We need a **descriptor**.

```python
class MyClassMethod:

    def __init__(self, func):
        self.func = func

    def __get__(self, instance, owner):
        def bound(*args, **kwargs):
            return self.func(owner, *args, **kwargs)
        return bound
```

Usage:

```python
class A:

    @MyClassMethod
    def hello(cls):
        print(cls)

A.hello()
```

Output:

```
<class '__main__.A'>
```

Why it works:

```
descriptor.__get__(instance, owner)
owner = class
```

So we inject the class.

# Exercise 4

### Implement `@staticmethod`

Static method disables binding.

```python
class MyStaticMethod:

    def __init__(self, func):
        self.func = func

    def __get__(self, instance, owner):
        return self.func
```

Usage:

```python
class A:

    @MyStaticMethod
    def hello():
        print("hi")

A.hello()
A().hello()
```

Works both ways.

Because we returned **raw function**.

# Exercise 5

Code:

```python
class A:

    @staticmethod
    def f(self):
        print(self)

a = A()
a.f()
```

### Output

```
TypeError: missing required positional argument 'self'
```

### Why

`staticmethod` **does not inject anything**.

So call becomes:

```
f()
```

But function expects:

```
f(self)
```

Hence error.

People mistakenly think staticmethod gives `self`.
It **does not**.

# Exercise 6 (Important)

Code:

```python
class A:

    def f(self):
        print("A")

a = A()

m1 = a.f
m2 = a.f

print(m1 is m2)
```

### Output

```
False
```

### Why

Each time you access:

```
a.f
```

Python creates **new bound method object**.

Internally:

```
A.f.__get__(a, A)
```

This runs every time.

So:

```
m1 = new bound method
m2 = new bound method
```

Different objects.

But:

```python
m1.__func__ is m2.__func__
```

is

```
True
```

Because both reference the same function.


# Production Engineering Insight

Bad code:

```python
for i in range(1000000):
    obj.method()
```

Better:

```python
m = obj.method
for i in range(1000000):
    m()
```

Because:

```
obj.method -> creates bound method
```

Saving it avoids repeated allocations.

Tiny but real optimization.
