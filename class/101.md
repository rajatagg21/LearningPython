# 1. What a Class Really Is

Most people think:

> class = blueprint

That's **kindergarten level explanation**.

Reality:

```
class = object that creates objects
```

Everything in Python is an object.

```
print(type(int))
print(type(str))
print(type(list))
```

Output:

```
<class 'type'>
<class 'type'>
<class 'type'>
```

Now watch carefully.

```python
class A:
    pass

print(type(A))
```

Output:

```
<class 'type'>
```

Meaning:

```
A is an object
created by class: type
```

Hierarchy:

```
type
 └── creates classes
        └── classes create instances
```

Example:

```python
class Car:
    pass

c = Car()

print(type(Car))  # class
print(type(c))    # instance
```

Output

```
<class 'type'>
<class '__main__.Car'>
```

Production takeaway:

```
Classes are runtime objects created by metaclass "type".
```

You can even create classes dynamically:

```python
Car = type("Car", (), {})
```

Same as:

```
class Car:
    pass
```

# 2. Class Definition Execution

Another thing beginners don't know:

> **A class body is executed like a normal script.**

Example:

```python
class Test:
    print("Executing class body")

    x = 10
```

Output:

```
Executing class body
```

It runs **once during class creation**.

Internally Python does:

```
1. create empty namespace dict
2. execute class body
3. store variables in namespace
4. create class object
```

Proof:

```python
class A:
    x = 10
    y = 20

print(A.__dict__)
```

You will see something like:

```
{
 'x': 10,
 'y': 20,
 '__module__': '__main__',
 '__dict__': ...
}
```

Production takeaway:

```
Class body builds the class namespace dictionary.
```

# 3. Instance Creation

When you write:

```python
obj = Car()
```

Python actually does:

```
1. Car.__new__()
2. Car.__init__()
```

Example:

```python
class A:

    def __new__(cls):
        print("NEW called")
        return super().__new__(cls)

    def __init__(self):
        print("INIT called")

a = A()
```

Output:

```
NEW called
INIT called
```

Flow:

```
class call
   ↓
__new__ → creates object
   ↓
__init__ → initializes object
```

Production rule:

```
Never override __new__ unless you know exactly what you're doing.
```

---

# 4. **init**

Purpose:

```
initialize instance state
```

Example:

```python
class User:

    def __init__(self, name, age):
        self.name = name
        self.age = age

u = User("Raj", 25)

print(u.name)
```

Output

```
Raj
```

Common rookie mistake:

```
__init__ is NOT constructor
```

The constructor is:

```
__new__
```

# 5. Instance Attributes vs Class Attributes

This is **extremely important in production systems**.

### Class attribute

Shared across all instances.

```python
class Dog:
    species = "canine"

d1 = Dog()
d2 = Dog()

print(d1.species)
print(d2.species)
```

Output

```
canine
canine
```

---

### Instance attribute

Stored per object.

```python
class Dog:

    def __init__(self, name):
        self.name = name

d1 = Dog("Tom")
d2 = Dog("Jerry")

print(d1.name)
print(d2.name)
```

Output

```
Tom
Jerry
```

---

### Dangerous behavior

```python
class A:
    x = 10

a = A()
a.x = 20

print(A.x)
print(a.x)
```

Output

```
10
20
```

Why?

Because:

```
a.x created a new instance attribute
```

Production takeaway:

```
Instance attributes shadow class attributes.
```

# 6. Attribute Access (CRITICAL)

Python searches attributes in this order:

```
instance namespace
     ↓
class namespace
     ↓
parent classes (MRO)
```

Example:

```python
class A:
    x = 10

a = A()

print(a.x)
```

Python checks:

```
1. a.__dict__
2. A.__dict__
3. parents
```

Verify:

```python
print(a.__dict__)
```

Output

```
{}
```

Meaning:

```
x came from class
```

Now:

```python
a.x = 50

print(a.__dict__)
```

Output

```
{'x': 50}
```

Now lookup stops at instance.

# 7. self Concept

Beginners think:

```
self is keyword
```

Wrong.

```
self is just a variable name
```

Example:

```python
class A:

    def hello(obj):
        print(obj)

a = A()
a.hello()
```

Works.

Python internally does:

```
A.hello(a)
```

So:

```
instance.method()
↓
class.method(instance)
```

Production takeaway:

```
methods are just functions stored in class namespace
```

Proof:

```python
class A:
    def f(self):
        pass

print(A.__dict__)
```

You will see:

```
'f': <function A.f>
```

# 8. Instance Methods

Default method type.

```python
class Calculator:

    def add(self, a, b):
        return a + b

c = Calculator()

print(c.add(2,3))
```

Internally:

```
Calculator.add(c,2,3)
```

---

# 9. Class Methods

Operate on **class**, not instance.

Use decorator:

```python
class A:

    x = 10

    @classmethod
    def show(cls):
        print(cls.x)

A.show()
```

Output

```
10
```

Use cases in production:

```
factory methods
alternate constructors
config loaders
```

Example:

```python
class User:

    def __init__(self, name):
        self.name = name

    @classmethod
    def from_dict(cls, data):
        return cls(data["name"])
```

---

# 10. Static Methods

Static methods are just **namespaced functions**.

They **do not receive self or cls**.

```python
class Math:

    @staticmethod
    def add(a,b):
        return a+b

print(Math.add(2,3))
```

Production usage:

```
utility functions logically grouped with class
```

---

# Namespace Summary (MOST IMPORTANT)

Every object in Python has a namespace dictionary.

```
instance namespace → obj.__dict__
class namespace    → Class.__dict__
```

Example:

```python
class A:
    x = 10

    def f(self):
        pass

a = A()
a.y = 20

print(a.__dict__)
print(A.__dict__)
```

Output

```
{'y': 20}

{
 'x':10,
 'f':function,
 ...
}
```

---

# Attribute Lookup Algorithm

When accessing:

```
obj.attr
```

Python does:

```
1. obj.__dict__
2. class.__dict__
3. parent classes (MRO)
4. AttributeError
```

This rule explains **90% of Python class behavior**.
